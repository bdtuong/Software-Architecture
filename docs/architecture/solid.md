# SOLID design of Attendance Management

The service keeps HTTP and JWT handling in presentation/config, business rules in domain/application, and PostgreSQL operations in infrastructure. `src/server.ts` composes the production implementations.

| Principle             | Implementation                                                                                                                                                                                                                           | Verification or tradeoff                                                                                                                                                                                                                                                                        |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Single Responsibility | `AttendanceService` ingests events; `RequestCorrection`, `ReviewCorrection`, and `ListCorrections` handle separate correction workflows; `AttendanceQueryService` builds effective views; `PeriodService` finalizes and exports periods. | Each use case can change for its own business reason without editing the others. A period still owns both finalization and export because both use the same period revision and eligibility rules.                                                                                              |
| Open/Closed           | `CorrectionRequestRule` validates ADD, REPLACE, and VOID through an injected kind-to-rule map.                                                                                                                                           | A new request validation policy can be registered without editing `RequestCorrection`. Adding a truly new correction kind still requires updating the domain type, persistence schema, API validation, and effective-view behavior; the system does not claim those changes are extension-only. |
| Liskov Substitution   | `AttendanceEventWriter` specifies idempotent Event ID handling, evidence uniqueness, and atomic side effects.                                                                                                                            | A shared contract test runs against the in-memory adapter and, when `TEST_DATABASE_URL` is set, Prisma/PostgreSQL. The in-memory adapter also simulates period invalidation and audit effects used by HTTP tests.                                                                               |
| Interface Segregation | Repository contracts separate event writes, record reads and lookup, correction request writes and reads, review, and approved-correction reads.                                                                                         | Each application use case receives only the operations it calls.                                                                                                                                                                                                                                |
| Dependency Inversion  | Application services depend on repository and `EffectiveFactoryReader` ports. Domain access policy depends on the domain `Principal` type rather than JWT configuration.                                                                 | Prisma and JWT wiring stays at the composition boundary; tests inject in-memory implementations.                                                                                                                                                                                                |

The shared contract covers the event writer's observable behavior. It does not prove that every in-memory query and transaction matches PostgreSQL under concurrency; the live PostgreSQL integration test covers critical review, period, and audit flows.
